# Архитектура интеграции КриптоПро

```text
Flutter UI
   |
   v
CryptoProBridgeClient (Dart)
   | JSON over stdin/stdout, one request per process
   v
MedialogSign.CryptoProBridge.exe (.NET Framework 4.8, x64, STA)
   | COM automation
   v
CAdESCOM / CryptoPro CSP / Windows certificate store
```

## Почему отдельный Windows-компонент

Flutter Desktop не должен напрямую управлять COM-объектами КриптоПро. Отдельный компонент изолирует Windows-specific код, а Flutter получает типизированные результаты и коды ошибок. JSON-протокол локальный, процесс запускается без shell и получает запрос через stdin.

## Хранилище сертификатов

В текущей реализации читается хранилище `CurrentUser\\My` профиля Windows, под которым запущен процесс. Это не означает, что будут видны сертификаты другого пользователя, сертификаты LocalMachine или ключи, доступные только в другом контексте RDP.

## Типы подписи

Подписи создаются через `CAdESCOM.CadesSignedData` с типом CAdES-BES. Для `sign-detached` устанавливается detached-флаг; `sign-attached` использует attached-режим. Фактическую совместимость с принимающей системой и ожидаемый формат контейнера нужно подтвердить тестами.

## Ключевые ограничения первой версии

- нет автоматического импорта сертификатов или контейнеров;
- нет копирования закрытых ключей;
- нет автоматического отзыва сертификатов;
- нет проверки OCSP/CRL и построения политики доверия;
- нет серверного хранения PIN/паролей;
- нет прямой записи в базу Медиалог;
- отсутствует проверка совместимости формата подписи с конкретным контуром Нетрики.
