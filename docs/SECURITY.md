# Безопасность

## Закрытые ключи и PIN

- Bridge не экспортирует закрытые ключи.
- PIN не передаётся в JSON, аргументах командной строки, переменных окружения или логах.
- Не сохранять PIN в конфигурации Flutter, Windows Credential Manager без отдельного security design, текстовых файлах или базе приложения.
- Диалог PIN/подтверждения должен оставаться в штатном CSP/token UX. Для неинтерактивного режима требуется отдельная согласованная схема.
- Доступ к ключу должен быть минимально необходимым и ограниченным Windows ACL/правами пользователя.

## Сертификаты

`CurrentUser\\MY` определяется security principal процесса. Другой пользователь или Windows Service может видеть другой набор сертификатов и ключей. Наличие сертификата в хранилище не доказывает наличие доступного закрытого ключа.

`hasPrivateKey` проверяет связь сертификата с провайдером/ключевым контекстом. Фактический доступ может завершиться ошибкой из-за PIN, отсутствия токена, блокировки, отсутствия CSP или ACL.

## Файлы

- Входные и выходные пути передаются как UTF-8 строки.
- Не формировать командную строку из этих путей и не запускать shell.
- В production следует ограничить доступные каталоги и права записи. Текущая версия принимает произвольные локальные пути, поэтому её нельзя считать sandboxed.
- Выход сначала записывается во временный файл рядом с целевым и затем перемещается с заменой.
- В production нужно решить политику перезаписи, временных файлов, очистки и антивирусного сканирования.

## Протокол и логи

- Один запрос на процесс.
- Не логировать весь запрос без редактирования.
- Не включать в сообщения ошибок PIN, секреты, содержимое документа или данные закрытого ключа.
- `stdout` содержит только JSON. При добавлении логов писать в отдельный защищённый sink или `stderr`.
- Принимающая система должна проверять происхождение и целостность полученного результата.

## Подписание как юридически значимая операция

Перед production требуется подтверждение полномочий пользователя, согласие на подпись конкретного документа, неизменность файла между отображением и подписанием, аудит, защита от повторной отправки и точная фиксация thumbprint/серийного номера/времени/хеша/версии ПО.

Текущая версия Bridge сама по себе не обеспечивает полный audit trail, trusted timestamp, authorization workflow или tamper-proof журнал.

## Windows Server

Не запускать интерактивный Flutter UI или этот process-per-request bridge как Windows Service в Session 0. Для background signing нужна отдельная service/worker архитектура и отдельная оценка хранения ключей, PIN UX, токенов, изоляции пользователей и доступа к сертификатам.
