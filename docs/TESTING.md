# План тестирования и приёмки

## Общие правила

- Использовать тестовый документ, тестовый сертификат и тестовый контейнер/токен.
- Не использовать production private key для первичной отладки.
- Сохранять версии Windows, CSP, CAdES runtime, SDK, Flutter и Bridge build.
- Любой результат сравнивать с независимым валидатором и/или принимающей системой.
- Успешная сборка не равна успешной криптографической интеграции.

## Матрица сценариев

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| B-001 | `status` | JSON success, x64, состояние runtime/provider |
| B-002 | `list-certificates` без сертификатов | Пустой массив |
| B-003 | Сертификат без private key | `hasPrivateKey=false`, не предлагается для подписи |
| B-004 | Сертификат с private key | Отображены subject, issuer, thumbprint, validity |
| S-001 | Detached CAdES-BES | Создан непустой `.p7s` |
| S-002 | Attached CAdES-BES | Создан контейнер с содержимым |
| S-003 | Неверный thumbprint | `CERTIFICATE_NOT_FOUND` |
| S-004 | Закрытый ключ недоступен | Понятная ошибка CSP/key provider, процесс не падает |
| S-005 | Неподдержанный OID | `UNSUPPORTED_KEY_ALGORITHM` |
| V-001 | Проверка detached корректной подписи | `valid=true` |

## Криптографическая проверка

Для каждой операции подписи:

1. Сохранить исходный документ и его контрольный хеш в тестовом отчёте.
2. Подписать detached и attached отдельно.
3. Проверить обе подписи через `CadesVerify*`.
4. Проверить те же артефакты независимым CryptoPro/внешним валидатором.
5. Передать артефакт в тестовый контур принимающей системы.
6. Изменить исходный файл на один байт и убедиться, что detached verify не проходит.
7. Проверить результат при недействующем, отозванном и недоверенном сертификате на специально подготовленных тестовых данных.

## Проверки trust и timestamp

Отдельно протестировать:

- доверенную и недоверенную цепочки;
- истёкший сертификат;
- отозванный сертификат;
- недоступный OCSP/CRL;
- валидную и невалидную TSA timestamp;
- корректность проверки на момент подписания и на текущий момент;
- профили CAdES-BES/T/X Long Type 1/A, если они требуются принимающей системой.

## Windows Server / RDP

Проверить вход пользователя, блокировку, disconnect RDP, reconnect, logoff, reboot, недоступность токена, удалённый токен и смену пользователя. Зафиксировать, какие операции требуют интерактивного UI PIN.

## Критерии допуска

Production rollout запрещён до тех пор, пока:

- x64 сборка проходит на чистой целевой ОС;
- версии CSP/CAdES runtime документированы и совместимы;
- все критические сценарии signing/verify проходят;
- форматы detached/attached и профиль подписи приняты целевой системой;
- trust/OCSP/CRL/TSP поведение согласовано;
- security review и операционная модель закрыты.
