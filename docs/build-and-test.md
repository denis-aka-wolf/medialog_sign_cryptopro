# Сборка и проверка на Windows

## Требования

- Windows 10/11 x64;
- Visual Studio 2022 или Build Tools с .NET desktop build tools;
- .NET Framework 4.8 Developer Pack;
- установленный КриптоПро CSP и совместимый компонент CAdESCOM, зарегистрированный для x64;
- тестовый сертификат с доступным закрытым ключом.

## Сборка helper

Откройте `windows_bridge/MedialogSign.CryptoProBridge.csproj` в Visual Studio, выберите `Release | x64` и соберите проект. Ожидаемый файл:

`windows_bridge/bin/Release/MedialogSign.CryptoProBridge.exe`

Если проект собирается в другом каталоге, передайте фактический путь в `CryptoProBridgeClient`.

## Протокол helper

Каждый вызов: один JSON-объект в stdin, один JSON-ответ в stdout. Например:

```json
{"action":"status"}
```

Или:

```json
{"action":"list-certificates"}
```

Для подписи используйте реальные локальные пути и отпечаток сертификата из списка сертификатов. Не помещайте PIN-код в JSON-запрос.

## Минимальный чек-лист

1. `status`: обе COM-метки доступны.
2. `list-certificates`: сертификаты соответствуют ожидаемому Windows-профилю.
3. Подписать небольшой тестовый файл отсоединённой подписью.
4. Проверить подпись исходного файла.
5. Изменить один байт исходного файла и убедиться, что проверка завершается ошибкой.
6. Проверить сертификат без закрытого ключа.
7. Проверить отмену PIN-диалога, заблокированный носитель и истёкший сертификат.
8. Проверить кириллицу в путях, большие файлы, сетевые каталоги и запуск по RDP.
9. Подтвердить формат результата с системой, которая будет принимать подпись.

Не проводите тесты на реальных медицинских документах до утверждения процедуры обработки данных.
